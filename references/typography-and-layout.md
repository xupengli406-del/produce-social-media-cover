# 封面文字：先完整读懂，再设计造型

用于所有视觉方向。目标是让观众顺着一条明确路径读懂观看理由；整齐不等于平庸，变形也不自动增加吸引力。以下类型是可扩展的选择库，不是需要全部使用的效果清单。

## 1. 排字前作出四个决定

1. **完整文案**：锁定本次允许使用的文字、标点和英文大小写。视觉重排不等于改写文案；已确认文字不能偷偷删改以适应模板。
2. **语义单位**：人工标记不可拆词组，如“家人”“专业软件”“OpenAI”“15分钟”；保留名词、专名、数字单位及否定关系。列出可接受的语义换行位置。机器不会替你理解这些关系。
3. **阅读主次**：先看到哪句、再看到哪句？选择一个主焦点，可是问题、概念或收益，不强求概念词永远最大。不需要的品牌、标签、卡片直接省略。
4. **空间与类型**：依据真实人物轮廓、视线、道具、画幅和平台安全区，选择一种主排版类型；说明它为什么适合。通常只辅以一种强调手法，复杂组合须证明阅读仍顺畅。

在制作记录中简记：`完整文案 / 不可拆词组 / 可换行处 / 主阅读顺序 / 排版类型及理由 / 关键避让区`。记录留在项目源文件旁，不塞进封面。

## 2. 排版类型选择库

| 类型 | 适用条件 | 保持特色的方法 | 不适用或返修信号 |
| --- | --- | --- | --- |
| 连续标题块 | 完整提问、观点、故事；需要快速读完 | 主副字号、紧凑行距、局部色差、对齐与主体关系 | 为塞进一行缩小整句；只剩一串等大的字 |
| 句内关键词强调 | 句子本身有一个值得突出的词 | 同一阅读流中改变整词字重、颜色或尺度 | 把关键词抽到远处，迫使观众来回拼句 |
| 短语阶梯／斜向块 | 短句、有递进或对比，需要动势 | 按完整短语错位或整体倾斜，维持明确行序 | 字字独立跳动；斜向关系打乱上下句 |
| 轮廓环绕 | 人物或道具两侧确有可用空间 | 文字块顺着轮廓退让，短语内部保持紧凑 | 从人物左边跳到右边才能读完；把一个词撕成两半 |
| 连续弧线／路径字 | 很短的标题、口号或辅助词，有清楚路径 | 连续基线与自然字距，沿路径渐变方向 | 长问题绕一整圈；每字随机旋转、间距失控 |
| 人物前后叠字 | 有可靠分层、文字足够大且仍完整可认 | 用主体与背景建立深度，关键字前置或错开 | 遮掉决定意义的笔画、否定词、脸、手或身份特征 |

先选适用性，再选新奇度。不强制两行、三行、居中、全横排或同一字体。没有合适空隙时，放弃环绕比拆碎句子更好；不能为了使用某个开源组件而迁就它的默认版式。

## 3. 不可退化的语义与几何规则

- **允许换行，不允许拆词凑形。** 长句按自然短语换行；行宽不必相等。不要让“家／人”横跨不同文字块，也不要把问号丢在很远的空隙中。
- 默认以词或短语为最小独立变形单位。连续路径排字可以逐字沿同一平滑基线旋转，不等于每字任意移位；必须实际缩小检查连贯性。
- 加色、加粗等样式片段可以位于同一词内，但不能制造异常字距或分离基线。词内分色不是拆词；把词拆成几个各自摆放的装饰块才是问题。
- 有明确意义的单字标题，如“赞”“停”，可以独立成立。句尾无意义孤字、断开的专名和数字单位、悬空标点应返修；不能只用“1–3字”阈值否决设计。
- 字距使用字体正常排印关系作为起点，不为填满画幅拉出巨大的词内空隙。中文与英文混排须检查光学间距、基线和标点；避免问号比整句更像另一条标题。
- 字体加载完成后测量。采用实际字形范围并计入描边、阴影和变形后的外接范围；容器宽度或字符数估算不能代替最终字形。检查字体回退、缺字和中文笔画过粗。
- 安全区按目标平台和构图设定，不把一套像素边距推广到所有比例。文字与人物关键轮廓可先尝试短边约3%–5%的呼吸距离，再依据视觉调整；禁止“没碰上但顶得很紧”的无意相切。
- 有意前后重叠必须清楚，且不遮身份、手势、道具连接处或核心字。局部背景可以压在字后，不能靠整图压暗来救对比。

### 正反例：迁移原则，不复制文案

- 完整问题“你会把它当成家人吗？”可以按语义分行；“家人”整词加色仍紧邻上下文。不应做成“家　人　吗　？”四个散落的独立块。
- “操作专业软件”可把“专业软件”整体放大；不应把“专业”塞左侧、“软件”塞右侧，中间隔着人头。
- “15分钟学会基础操作”可在“15分钟”后换行；不应在“15／分钟”之间断开。
- “停”作为明确命令可以独立；完整句子为了避开人物只剩“的”一字落在下方，不可以。
- 弧形的短口号可以沿连续路径排；完整长问题若需要转头或绕过人物寻找下半句，应换类型。

## 4. 两道检查，不把脚本当审美裁判

### A. 确定性检查

在项目内保存一个排版 JSON 清单，使用最终渲染器测得的数据。每句完整标题对应一个 block，不能把一句拆成多个 block 来绕过检查。`runs` 按实际阅读顺序列出文字片段；同一连续基线／路径用同一 `flow` 和 `line`，独立摆放的字块必须有不同 flow。样式片段可以共用 flow，但不能把不连续散字虚报成同一流。

```json
{
  "canvas": [1242, 1660],
  "image_sha256": "填写本次封面PNG的SHA256",
  "safe_rect": [48, 48, 1146, 1564],
  "keepouts": [{"id": "face-with-clearance", "rect": [450, 650, 300, 300]}],
  "blocks": [{
    "id": "question",
    "text": "你会把它当成家人吗？",
    "atomic": ["家人"],
    "runs": [
      {"text": "你会把它当成", "flow": "question-top", "line": 0, "rect": [100, 100, 700, 100]},
      {"text": "家人吗？", "flow": "question-bottom", "line": 1, "rect": [100, 230, 650, 150]}
    ]
  }]
}
```

以上只是合成数据，不能作为真实测量结果复用。矩形统一为像素 `[x, y, width, height]`；`keepouts` 只放不可覆盖的关键区域，并含本图所需避让距离，不能用整个人物的粗框否决合理分层。可用多矩形逼近轮廓；宽松外接框引发疑似误报时，细化实测区域，不删除真实禁区。`atomic` 可为空，但必须经过人工语义检查。

运行 `python scripts/validate_typography.py <清单.json> --image <本次封面.png>`。检查原文漏字／重复／顺序、标记词组跨行或跨独立流、文字越界及关键区域重叠，并核对PNG尺寸和文件指纹，防止拿旧清单为新图背书。清单与图均变更后重新测量、检查。

脚本无法证明清单测量真实、不会自动分词，也不检测字体美感、词内异常字距、图中文字实际内容、语义合理性、光学相切或吸引力。没有测量能力时明确报告未完成此检查并补齐测量，不得填假数据或宣布完整验收。

### B. 实际视觉复核

逐比例查看原图及手机缩略图：3:4约300×400，9:16约270×480，4:3约400×300。所有保留的关键文字都应可读；可以先看标题再看次要内容，不要求所有字同大。

1. 不凭文案记忆补字，从成图按自然顺序读一次。是否要猜字、跳跃或回头找下半句？
2. 先注意到的文字是否就是本期观看理由？文字、脸和主题物是否互相抢焦点？
3. 强调词与原句是否仍是一句话？缩小后弧线、描边、阴影、分色有没有把字粘在一起或拆散？
4. 检查脸、发际线、手、道具接触处，以及边缘文字和平台裁切；检查无意相切，不能只看矩形是否相交。
5. 如果造型要解释才能读懂，先重组短语、换排版类型或移动文字区，再调整主次；不能仅缩小全部字体。改文案需要符合用户授权范围。

发布说明只需记录所选类型、主要修正、确定性检查和实际看图结论。不宣称“脚本保证爆款”。新方向仍遵守先小样、确认后扩展比例的流程。
